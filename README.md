# spidiboost.SpidiCard 1.4.0 — Fabric 1.21.4

<img src="src/main/resources/assets/spidicard/icon.png" width="160" alt="SpidiCard icon">

Автор: **SpidiBoost**.

Независимый клиентский мод: Minecraft 1.21.4, Java 21, Fabric Loader от 0.16.10 и
Fabric API для 1.21.4. Требуется серверный доступ к `/invsee <ник>`.

Скачайте JAR из [последнего релиза](https://github.com/SpidiBoostMods/SpidiCard/releases/latest)
и положите `SpidiCard-1.21.4-1.4.0.jar` в `mods` нужного экземпляра Minecraft.
Старую версию SpidiCard нужно заменить, чтобы в `mods` был только один его JAR.

## Автообновление с GitHub

Начиная с 1.4.0 мод проверяет последнюю опубликованную версию при запуске клиента
и при подключении к серверу, включая одиночный мир. Проверка и скачивание идут в
фоновом потоке. Если GitHub недоступен, проверка инвентарей продолжает работать;
следующее подключение снова вызывает проверку. Одновременные проверки объединяются.

При обновлении проверяются номер версии, Minecraft 1.21.4, SHA-256, идентификатор и
версия внутри JAR. Старые и несовместимые версии не устанавливаются. Перед
перезапуском активная проверка останавливается с сохранением найденных ников.
Отдельный Java-процесс дожидается полного закрытия игры, сохраняет резервную копию
и заменяет тот же файл в `mods`. Настройки, другие моды, миры и результаты сохраняются.
Временные файлы, резервные копии и журнал находятся в `.spidicard` текущего инстанса.
Ссылки на общие внешние каталоги `mods` и запуск из папок разработки не обновляются.

Prism определяется по реально работающему процессу лаунчера и `instance.cfg`;
перезапуск использует `--dir` и `--launch` текущего инстанса, включая переносимые
установки и имена с пробелами. Для других лаунчеров поддерживается прямой запуск
Fabric KnotClient через Java: сохраняются исходные аргументы и рабочая папка.
Никакие команды оболочки и разбор строки по пробелам не используются. Аргументы
авторизации передаются помощнику через stdin и не записываются на диск или в журнал.

Некоторые версии KLauncher, FLauncher, TLauncher, Legacy Launcher и Prism используют
свои обёртки, временные файлы аргументов или обмен данными с лаунчером. Такой запуск
нельзя гарантированно повторить из мода: в этом случае появляется уведомление,
обновление устанавливается после обычного выхода, а игру нужно запустить через
лаунчер самостоятельно. Автоматическое повторное подключение к серверу не выполняется.
Проверка помощника на трёх ОС не означает проверку каждой сборки этих лаунчеров.

Версии до 1.4.0 не содержат обновляющего кода: **1.4.0 впервые устанавливается вручную**.
Последующие выпуски публикуются в GitHub Releases вместе с `spidicard-update.properties`.
Для публикации измените `mod_version`, выполните проверки и отправьте тег `vX.Y.Z`.
Workflow сначала запускает тесты на Windows, macOS и Linux, затем создаёт релиз с
JAR, исходниками и контрольной суммой. Токен публикации хранится только на стороне GitHub.

## Исключения и подсчёт

Ник `SpidiBoost` никогда не проверяется, без учёта регистра. Собственный ник берётся
из текущей записи таба по UUID игрока, полученной от сервера; если её ещё нет — из
текущего игрового профиля игрока. Ник из launch-session не используется.
Исключение проверяется при создании очереди и перед каждым запросом, поэтому
изменение текущего ника во время работы учитывается. Исключённые ники не попадают
в результаты.

Карты определяются только по названиям `Синяя Ключ-Карта`, `Красная Ключ-Карта`,
`Зелёная Ключ-Карта`. Цвета и другое форматирование не учитываются; регистр,
`ё/е`, дефисы и пробелы нормализуются. Суммируется количество предметов в стаках
всех трёх цветов: 2 синие + 1 красная = 3. Нижний собственный инвентарь не считается.
Переименование обычного предмета в точно такое название также считается картой,
поскольку проверка намеренно выполняется исключительно по имени.

## Команды

| Команда | Назначение |
| --- | --- |
| `/spidicard count 3` | Общая сумма карт не менее 3; по умолчанию 1 |
| `/spidicard count` | Показать текущий порог |
| `/spidicard start` | Проверить актуальный снимок таба на текущем сервере |
| `/spidicard full` | Автоматически обойти грифы 1–56 |
| `/spidicard full 3` | Начать с грифа 3 и обойти грифы 3–56 |
| `/spidicard full 3-5` | Проверить только грифы 3–5 |
| `/spidicard full 3-5, 8-12, 53, 56` | Проверить указанные диапазоны и отдельные грифы |
| `/spidicard stop` | Остановить обычную проверку или весь полный обход |
| `/spidicard menu` | Повторно открыть окно с последними сохранёнными результатами |
| `/spidicard status` | Показать этап, номер грифа и прогресс проверки |
| `/spidicard delay 0` | Убрать дополнительную паузу между инвентарями |
| `/spidicard timeout 5000` | Максимальное ожидание окна/содержимого, в миллисекундах |

Задержка по умолчанию 100 мс, диапазон 0–10000. Таймаут по умолчанию 5000 мс,
диапазон 500–60000. Настройки сохраняются в `config/spidicard.properties`.
Изменения во время работы применяются к следующему запуску. В полном обходе порог,
задержка и таймаут фиксируются на весь проход, чтобы все грифы проверялись одинаково.
Альтернативное написание `/spidicart ...` тоже работает.

## Окно результата на Windows и macOS

После окончания `/spidicard start` или `/spidicard full`, включая досрочную
остановку `/spidicard stop`, Escape, ошибку проверки, кик или обрыв соединения,
предыдущее окно результатов этого экземпляра закрывается и открывается новое.
Показан свежий текст `spidicard.txt`; строки грифов без найденных игроков скрыты
только в окне, а файл сохраняет полный отчёт. Счётчик грифов учитывает видимые
результаты. ПКМ открывает меню «Копировать выделенное», «Копировать всё»,
«Выделить всё». Выделение копируется через Cmd+C на macOS и Ctrl+C на Windows;
Cmd+A / Ctrl+A выделяют всё. Есть кнопки копирования и открытия папки.
Файл остаётся обычным UTF-8 текстовиком. При прерывании показываются уже найденные
ники; в full сохраняются завершённые грифы и найденные ники текущего грифа.
Повтор проверки внутри продолжающегося full и промежуточная запись очередного
грифа не открывают окно. Окно появляется после успешной записи свежего результата.

Если окно закрыто, `/spidicard menu` открывает его снова из сохранённого
`spidicard.txt` этого экземпляра. Команда не запускает проверку и не перезаписывает
ники. Работает для результатов start, full и досрочно прерванной проверки,
включая результаты после перезапуска Minecraft. Пустой сохранённый результат
тоже открывается; при отсутствии файла показывается сообщение в чате.

Путь берётся из `FabricLoader.getGameDir()` текущего запущенного экземпляра,
без привязки к Prism, `.minecraft`, тестовой папке или имени пользователя.
Окно запускается отдельным Java-процессом: на Windows используется
`java.home/bin/java.exe`, на macOS — `java.home/bin/java`. Пути передаются
отдельными аргументами без shell: пробелы, кириллица и спецсимволы сохраняются.
Просмотрщик входит в JAR, дополнительных модов или программ не требует.
Он закрывает только своё предыдущее окно; документы Блокнота, TextEdit и других
редакторов не затрагиваются. После выхода из Minecraft окно закрывается.

## Обычная проверка

Мод отправляет по одному `/invsee`, ждёт полного пакета инвентаря и 50 мс без
изменений его верхних слотов, затем закрывает окно и переходит к следующему нику.
В 1.3.3 окончание этой паузы проверяется также между игровыми тиками: после
обработки очереди сетевых пакетов на главном потоке клиента. Следующий запрос
может уйти раньше, без округления ожидания до очередного игрового тика. Любое
обновление верхних слотов по-прежнему заново отсчитывает 50 мс. Значение `delay`
сохраняется, параллельные `/invsee` не отправляются. При низком FPS остаётся
обычная проверка на игровом тике; пропущенное время не запускает пачку запросов.
Проверки загрузки хаба, грифа, таба и таймауты не сокращены.
Свежий syncId защищает от пакетов предыдущих окон. Если заголовок содержит ник из
очереди, проверяется соответствие текущему запросу.

По завершении один файл `spidicard.txt` в папке игры, рядом с `mods`, `config` и
`logs`, содержит ники через один пробел в одной строке. Следующий проход
перезаписывает этот же файл; при отсутствии совпадений он становится пустым.
При остановке или ошибке сохраняется частичный результат, о чём мод сообщает в чате.

Понятный серверный ответ «игрок не найден/не в сети» пропускает этого игрока.
Таймаут обычного `/start` останавливает проход: отсутствие ответа не считается
пустым инвентарём. После прерывания новый запрос ждёт время `timeout`, чтобы
запоздавшие ответы не попали следующему игроку.

## Полный обход `/spidicard full`

Необязательный номер от 1 до 56 задаёт первый гриф: `/spidicard full 3`
проверяет только грифы 3–56, `/spidicard full 56` — только гриф 56.
Без номера обход начинается с 1.

Если аргумент содержит дефис или запятую, проверяются только выбранные грифы:
`full 3-5` — 3, 4, 5; `full 3-5, 8-12, 53, 56` — 3, 4, 5, 8, 9, 10, 11, 12,
53, 56. Пробелы вокруг запятых и дефиса допустимы. Номера сортируются по
возрастанию; повторы и пересечения диапазонов проверяются один раз.
Для одного конкретного грифа используйте, например, `full 53-53`.
Один номер без дефиса и запятой сохраняет прежнее значение: от него до 56.
Все номера должны быть 1–56, начало диапазона не больше конца. Пустые элементы
и любая ошибка отклоняют всю команду до запросов на сервер и записи результата.

Для номера от 33 сразу выбирается вторая страница. В результате сохраняются фактические номера проверенных грифов;
пропущенные грифы не добавляются. Это новый проход с перезаписью результата,
как у обычного full, а не объединение с предыдущим файлом.

1. Отправляется `/hub`; ожидается `minecraft:compass` в первом слоте хотбара
   с названием `ВЫБОР СЕРВЕРА (ПКМ)` без учёта форматирования.
2. Выбирается первый слот хотбара и используется компас правой кнопкой.
3. Как только сервер присылает предмет `ГРИФ ВЫЖИВАНИЕ (1.21.11)` в слоте 21
   меню `Выбор сервера`, мод сразу отправляет клик. Не ждёт дополнительного тика.
4. В меню `Выбор мира грифа` проверяются страница, слот и название `ГРИФ #N`.
   Клик по нужному грифу повторяется каждые 400 мс, пока соответствующее меню
   остаётся открытым. Посторонний предмет или другой номер не нажимается.
5. Для грифов 33–56 сначала нажимается стрелка `Следующая страница` в слоте 44.
   Пока вторая страница не появилась, мод не нажимает целевой слот на первой.
6. Фаза конфигурации при переключении серверов не считается отключением:
   даже если игровой сетевой обработчик, игрок и мир временно отсутствуют,
   полный обход сохраняется, пока физическое соединение открыто. В это время
   команды и клики не отправляются.
7. Перед действиями проверяются завершение загрузки игрока (`isLoaded`),
   наличие чанка на его позиции, отсутствие экранов загрузки/конфигурации и
   500 мс готового мира. Само закрытие меню или обновление пинга в табе не
   подтверждает вход на гриф. Нужны смена мира, серверная позиция, смена состава
   таба или новый номер грифа в scoreboard; scoreboard необязателен.
   Перед `/invsee` таб должен содержать собственную запись игрока и оставаться
   стабильным 750 мс. Если в табе пока только собственная запись, ожидание
   увеличивается до 5 секунд: это защищает от пустого результата при поздней
   загрузке остальных игроков. После промежуточной загрузки отсчёт начинается заново.
8. Если меню компаса/грифов/второй страницы пропало или не появилось за 5 секунд
   готового мира, мод открывает выбор текущего грифа заново. Если меню закрылось,
   а переход не подтвердился за 15 секунд готового мира, повторяется выбор
   этого же грифа. Незагрузившийся таб повторно проверяется до 30 секунд, затем
   повторяется подключение к этому же грифу. Время фактической загрузки мира
   не расходует эти таймауты. Номер грифа увеличивается только после успешной
   проверки. Во время ожидания каждые 5 секунд выводится текущий этап.
9. Запускается та же проверка карт. Недоступные игроки пропускаются. Если проверка
   не завершилась, включая ситуацию, когда `/invsee` ещё не работает, после
   ожидания повторяется `/start` на этом же грифе. Повторный заход через `/hub`
   при таком сбое не выполняется. Позднее окно старого `/invsee` закрывается.
   Если сервер действительно вернул игрока в хаб, обход возвращается на тот
   же незавершённый гриф и продолжает проверку.
10. Успешный результат грифа записывается, затем мод возвращается в хаб для
   следующего грифа. После 56-го грифа работа завершается на нём.

Файл тот же — `spidicard.txt`; в полном режиме в нём отдельная строка на каждый
проверенный гриф:

```text
nick1 nick2 - grief #1
nick3 - grief #2
- grief #3
```

Гриф без совпадений получает строку `- grief #N`. После каждого завершённого грифа
тот же файл атомарно перезаписывается всеми уже готовыми строками. При `/stop`
сохраняются готовые грифы и найденные ники частично проверенного текущего грифа.
При остановке ещё на этапе навигации строка непроверенного грифа не добавляется.
Успешный повтор проверки заменяет частичную попытку этого грифа, не накапливает
устаревшие совпадения из предыдущей попытки.

Во время работы не отправляйте `/invsee` через другой мод и не открывайте другие
серверные меню. Перенос предметов и горячие клавиши в управляемых окнах блокируются.
Escape, как и `/spidicard stop`, останавливает работу. Команды `/start` и `/full`
не запускаются параллельно.

## Переходы и обрыв соединения в 1.3.5

После успешного завершения грифа результат сначала сохраняется. Перед следующим
`/hub` мод ждёт 500 мс; если за это время приходит запоздавшее окно, закрывает его
и снова ждёт 500 мс. Переход не накладывается на закрытие последнего `/invsee`.
Добавленная пауза относится только к переходу между грифами, не к игрокам внутри
проверки. Для полного маршрута без повторов добавляется около 27,5 секунды.

Открытый экран загрузки не считается доказательством работающего соединения.
Состояние берётся из исходного транспортного соединения: пока оно открыто,
переключение play/configuration/play продолжает ожидание; после фактического
обрыва проверка завершается с сохранением найденных ников. Повторное подключение
с новым соединением не продолжает старый проход. Команды, клики и использование
компаса не отправляются в закрытое соединение.

Пауза перед `/hub` — мера для разделения действий на границе серверов. Она не
гарантирует устранение ошибки сжатых данных на сервере или прокси. Источник
`invalid distance too far back` по одним клиентским логам не установлен.

## Сборка и проверка

На Java 21: `./gradlew build`. Основной JAR:
`build/libs/SpidiCard-1.21.4-1.3.9.jar`. Тестовые классы в него не включаются.

65 автотестов покрывают 300 игроков, все 56 номеров и слотов, две страницы,
форматирование названий, стаки, собственные слоты, текущий ник и его изменение,
запоздавшие пакеты, ожидание таба, повтор клика, повтор проверки без нового `/hub`,
перезапись файла и остановку на этапах маршрута.

Проверка 300 игроков на одинаковом локальном серверном сценарии при `delay 0`
заняла 33,97 секунды в 1.3.2 и 28,25 секунды в 1.3.3. В обоих случаях отправлено
ровно 300 уникальных запросов и записано 150 одинаковых совпадений. Замер выполнен
на macOS в отдельном клиенте с лимитом 120 FPS и отключённым VSync; время открытия
просмотрщика в замер не входит. Это результат локального сравнения, не обещание
такого же ускорения на ReallyWorld: пинг, FPS и скорость ответа сервера влияют

## Обработка инвентарей в 1.3.9

Полный пакет создаёт отдельный счётчик вкладов слотов. Последующий пакет одного
слота заменяет только его вклад; остальные слоты повторно не читаются. Повторный
полный пакет целиком заменяет счётчик. Кэш распознавания названий общий для одного
прохода и ограничен 256 значениями; количества и собственные слоты каждого окна
учитываются отдельно. Перед полным пакетом обновления слотов не завершают чтение.
Порог, ожидание 50 мс, порядок запросов, таймауты и проверки загрузки сохраняются.

В конце прохода строка `Scan timings` в `logs/latest.log` показывает среднее время
запрос → окно, окно → полный пакет и полный пакет → следующий игрок. Это позволяет
отличить задержку ответа сервера от времени обработки инвентаря.

Кратное ускорение полного прохода не подтверждено. Эксперимент без создания GUI
для каждого инвентаря отклонён: в локальном сравнении с одинаковым лимитом 120 FPS,
отключённым VSync, без AFK-снижения FPS и при `delay 0`, `timeout 5000` обычный GUI
проверил 300 игроков за 25,10 секунды, скрытый — за 26,30 секунды. В обоих случаях
получены ровно 150 одинаковых совпадений. В релизе остаётся обычный GUI; его FPS
настройки не меняются. Оптимизация счётчика снижает работу на пакет слота и повторное
распознавание названий, но не сокращает время ответа `/invsee` на сервере.

При 50 мс ожидания последовательная проверка 300 игроков занимает минимум
15 секунд даже без сетевой задержки. Следующий `/invsee` может закрывать предыдущий
серверный инвентарь и отменять его догрузку, поэтому параллельные запросы не
включены. Проверка `./gradlew runVerification -PqaSpeedSafety` использует реальные
отложенные добавления/удаления карт, повторный полный пакет, Q и Escape,
сохранение полного и частичного результата и замену окна просмотра.

## Оформление чата и ошибок в 1.3.8

Префикс `[SpidiCard]` использует фиолетово-голубой градиент, текст сообщений —
светлый голубовато-сиреневый, ошибки — розово-коралловый с тёплым концом.
По буквам плавно проходит мягкий световой перелив с периодом 6 секунд.
Изменение цветов выполняется при отрисовке: строки чата не переписываются,
новые сообщения ради анимации не добавляются. Обычный чат и другие моды сохраняют
свои стили. Маркеры шрифтов используют стандартные символы Minecraft; переносы,
Unicode, размеры текста и выбор предметов не меняются.

Ошибки команд, включая неверные списки, count/delay/timeout и неизвестные
подкоманды, выводятся локально: крупный градиентный титул по центру, короткая
подсказка ниже и подробность в чате. Появление — 8 тиков, показ — 52, исчезновение —
18. Ширина титула и подсказки ограничивается текущей шириной игрового интерфейса.
Команда `/title` на сервер не отправляется. Титул не блокирует управление и
исчезает сам. Обычная остановка пользователем остаётся обычным сообщением.
Повторные ожидания загрузки в full не создают титул ошибок.

Для собственных команд сохраняется тот же клиентский dispatcher Fabric;
оформление ошибок обрабатывает только точные корни spidicard и spidicart.
Другие клиентские и серверные команды используют прежний путь выполнения.

В отдельном настоящем клиенте проверены загрузка миксинов, градиентные цвета,
изменение цветов со временем, сохранность обычных стилей, Unicode и ширины букв,
ошибки через настоящий исполнитель Fabric, отсутствие запросов на сервер и
изменений результата при неверной команде, титул и его автоматическое исчезновение.
Кадры интерфейса сохранены и просмотрены. Через тот же исполнитель проверены
обычный start и алиас full 56-56: точные ники, запись файла и замена окна
результатов сохранены. Команда проверки: `./gradlew runVerification -PqaStyle`;
отчёт `chat-style-results.txt`. Это локальный сценарий на macOS; ReallyWorld и
живой Windows-клиент в этом прогоне не тестировались.
